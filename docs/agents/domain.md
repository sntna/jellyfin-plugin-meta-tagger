# Domain documentation

Read the public [domain glossary](../../GLOSSARY.md) before exploring the repository.
Use its names consistently and update definitions when an approved behavior change
changes their meaning. Keep definitions about domain concepts; implementation
details belong in the development guides.

This repository uses one root `CONTEXT.md` and `docs/adr/` for local context and decisions.
Read them when present, especially decisions relevant to the change. Proceed
silently if absent; create them when domain terms or decisions are resolved.
These are ignored local development notes. Never stage or commit them.
Flag conflicts with existing ADRs. The public glossary is tracked documentation,
not a local development note.
